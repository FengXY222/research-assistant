# 科研助手 v11.1 Acceptance and Journal Quality Design

## Goal

Finish the v11.1 desktop release as a dependable personal research-work manager: settings must remain responsive, the core HOME / WORK / PAPERS flows must be visually coherent and directly usable, and journal quality data must be visible and enforceable before an installer is produced.

## Release Constraints

- Platform: Windows desktop application built with Python and PySide6.
- Formal user data remains in `C:\Users\fxy17\AppData\Local\Programs\科研助手\data`; no release operation may overwrite, migrate, or delete it without a verified backup.
- EasyScholar is optional and uses a user-owned key stored through the existing secure-store path. Keys must never appear in logs, screenshots, tests, plans, or error messages.
- Existing handwritten JCR / Clarivate records remain authoritative. EasyScholar contributes a separately labelled cached snapshot and must not overwrite a locked/manual JCR value.
- No installer is built until automated tests and live desktop acceptance checks pass.

## UX Decisions

### Appearance and responsiveness

The application keeps its semantic palette architecture. A theme or density change refreshes the application stylesheet exactly once; an unrelated Settings save is a no-op for styling. The picker retains a balanced set of light and dark palettes with clearly distinct hue families, including teal, red-coral, violet, blue-orange, green, and dark high-contrast variants.

All ordinary inline actions use the base interface text size. Only controls that are intentionally graphical or draggable keep enlarged treatment. This removes oversized action labels from Daily Frontier, paper submission cards, and Research Profile without shrinking their click targets.

### HOME, WORK, and PAPERS

HOME has three non-duplicated purposes: an explicit list of unfinished tasks for today, the single most actionable next step, and a compact recent-activity trail. Its note buttons must fit at every supported width. A paper next step carries paper and journal IDs into PAPERS, expands the matching paper, scrolls its target journal into view, and gives it a transient visual attention state.

WORK exposes an immediate priority control as the primary path. Dragging remains an optional reordering affordance, with a clear quadrant overlay and readable labels. PAPERS keeps the rejection archive as a corner entry point rather than a page-width competing panel.

### AI-first journal selection

The journal-selection dialog begins from the paper title, abstract, local research profile, existing submission history, and user requirements. Requirements include open-access preference, target JCR quartile, a known-Q3/Q4 filter, and a publication-speed preference called "发表时效". AI fit drives the ranking, while verifiable local constraints contribute bounded quality and risk adjustments. AI may nominate external journals; those can be added to the library through a fast, reviewable import action before they are used in a submission path.

### Journal quality data

Journal data is normalized into two layers:

1. `jcr`: the current authoritative JCR status, source, date, and quartile.
2. `easyscholar`: separately labelled cached metadata such as CAS upgrade/basic divisions, impact factors, EI/ESCI status, and source timestamp.

The Daily Frontier default feed is quality-gated. When a journal has a current JCR value, Q3/Q4 is excluded. When EasyScholar is configured and the quality check has completed, the normal feed contains only verified Q1/Q2 journals; unresolved titles are held out of the default feed rather than silently treated as high quality. A visible empty or pending state explains when no eligible verified sources are available. The Journal Library, AI selector, and Daily Frontier all show a concise metric line, for example `JCR Q1 · 中科院升级版 2区 · IF 5.6`, with the source and checked date available in details.

EasyScholar refreshes stale records asynchronously, reuses the existing cache interval, and never blocks the GUI. Daily Frontier uses library/cached journal identities for quality decisions; it must not make a paid/provider request on the UI thread.

## Acceptance Criteria

- Switching from a light palette to a dark coral palette visibly changes already-open cards, settings, and popups; saving an unrelated setting does not rebuild the application stylesheet.
- Daily Frontier, submission records, and Research Profile show standard-sized row actions with no clipping or overlap at normal and compact density.
- HOME, WORK, PAPERS, and LIBRARY satisfy the navigation and layout behavior listed above on real Windows rendering, not only in offscreen unit tests.
- The selector accepts and ranks external AI candidates, honors OA/quartile/speed requirements, and exposes a fast import action.
- A verified EasyScholar fixture renders CAS division in all three journal-facing views. A configured quality gate never emits known Q3/Q4 results into the default frontier; after a successful EasyScholar check, it emits only Q1/Q2 into that default feed.
- Automated tests pass, live desktop screenshots are reviewed, a new hash-verified data backup exists, the installer is built, installed to the formal directory, and launched successfully with the preserved data counts intact.
