# 科研助手 v10.0.0 设计规格

## 1. 目标与边界

**目标：** 在不删减既有业务能力、不改变本地 JSON 数据模型、不破坏正式安装升级与 PDF 链接的前提下，重做科研助手的应用外壳、信息层级、主题系统和设置界面。

v10 的问题不是“功能少”，而是过多功能被并列展示为一级页面，视觉上又混用了深色透明叠层、重复标题、常驻低频操作和彼此无关的颜色。v10 应保留用户已调顺手的窗口比例、侧边标签、首页卡位、拖拽/置顶/锁定/全局快捷键和所有数据入口；改变的是功能归属、页面层级和视觉规则。

本版本的范围仅限于 UI、信息架构、设置和兼容迁移。以下内容明确不新增：数据库、云同步、账户体系、服务端、联网权限模型或新的业务数据类型。

## 2. 已确认的产品决策

| 决策 | v10 定义 |
| --- | --- |
| 默认主题 | 雾青蓝（Fog Teal） |
| 主题机制 | 设置中提供六套完整主题，点击后即时预览，保存后持久化 |
| 小组件模式 | 保留当前无边框、可拖动、侧边标签、紧凑首页与常驻桌面的使用方式 |
| 软件模式 | 同一应用、独立窗口尺寸配置；四个工作台按单一连续页面展开，侧栏只滚动定位，不切换页面 |
| 一级结构 | HOME / WORK / PAPERS / LIBRARY 四个工作台 |
| 数据策略 | 继续使用现有本地 JSON；不删除、不重建、不迁移论文、成果、PDF 链接或备份数据 |
| 安装升级 | 延续正式安装版的原地升级与数据保留策略；v10 仅覆盖程序文件，不覆盖 `data` |

## 3. 功能重新编排

### 3.1 四个工作台

| 工作台 | 保留的功能 | 默认目的 | 小组件中的子区 | 软件模式中的位置 |
| --- | --- | --- | --- | --- |
| HOME | 科研概览、今日摘要、论文状态、最近节点、每日科研简报 | 快速判断今天最该做什么 | 无额外子区；维持现有首页卡位 | 连续页面顶部 |
| WORK | 今日待办、无时间任务、循环任务、未完成迁移、历史任务、灵感便签、值得阅读 | 处理当日研究执行与随手记录 | 今天 / 灵感 / 待读 | HOME 之后 |
| PAPERS | 投稿记录、多期刊经历、逐期刊编辑、时间线、投稿提醒、拒稿归档、成果（论文/专利/奖项）、PDF 链接 | 管理论文全生命周期 | 投稿 / 归档 / 成果 | WORK 之后 |
| LIBRARY | 期刊库、JCR、出版社和标签、选刊、每日前沿、研究画像、公开数据源、DeepSeek 补全与更新 | 管理外部研究资源与选刊判断 | 前沿 / 期刊 / 选刊 / 画像 | PAPERS 之后 |

### 3.2 归属原则

- **TODAY 不消失。** 它变为 WORK 的“今天”子区，仍可从 HOME 双击、侧栏单击、快捷操作直接进入。
- **灵感与待读不消失。** 它们继续同页呈现，成为 WORK 的“研究笔记”区；原有新增、编辑、标记已读、排序动作全部保留。
- **成果不再单独占一级入口。** 论文接受/发表自动归档成果、PDF 链接、研究画像更新等仍保留，归属于 PAPERS 的成果子区。
- **期刊与每日前沿不再平行占两个大入口。** 二者统一为 LIBRARY，但仍提供直接锚点、搜索和首页跳转。期刊选择、JCR 补全、前沿推荐算法和每日更新均不降级。
- **拒稿归档保留在 PAPERS。** 它仍按“单个论文的单个期刊”归档，不能影响同一论文的其它期刊经历。

### 3.3 交互路径

- 小组件侧边标签从 7 个缩减为 4 个，仍支持左/右位置、自动隐藏、固定展开、标签显示延迟和窗口锁定。
- WORK、PAPERS、LIBRARY 在小组件内各有 2–4 个轻量子区按钮；子区不是新的大页面，切换后记住本次会话的最后位置。
- HOME 中的任务、论文状态、最近节点、每日简报、灵感、待读卡片继续支持双击直达相关工作台和具体子区。
- 软件模式的顶部锚点只负责滚动定位 HOME、WORK、PAPERS、LIBRARY；不使用 `QStackedWidget` 产生页面切换感。
- 所有“新增、编辑、删除、排序、归档、打开 PDF、选刊、更新、提醒处理”能力继续在其原来的业务上下文中出现；低频动作收纳为行悬停操作或“更多”菜单。

## 4. 双模式应用壳

### 4.1 小组件模式

- 保持无边框、可拖动、可缩放、可置顶、可透明、可锁定、可点击穿透、可托盘隐藏的桌面便签属性。
- 保留当前首页空间关系：顶部轻量栏、边缘竖排标签、上部状态概览、最近节点、下部辅助内容。
- 取消默认透明叠层：默认主题以不透明表面保证下拉菜单、文本和弹窗的可读性。透明度仍为 20%–100% 可调选项。
- 保留窗口位置、尺寸与锁定状态；收起后展开必须恢复完整的先前几何信息。
- 保留全局显示/隐藏快捷键（含双击空格与可自定义组合键）；中文输入法处于组合输入状态时必须禁用双击空格触发，避免干扰正常输入。

### 4.2 软件模式

- 使用独立的窗口几何配置，默认建议尺寸为 1180×820；最小尺寸不低于 920×680。
- 同样使用科研助手的自定义顶部栏和侧边标签，但内容区改为单一 `QScrollArea` 工作台。
- HOME、WORK、PAPERS、LIBRARY 依次形成连续区块；在窄窗口时列布局自动纵向堆叠，不裁切、不隐藏必要文字。
- 小组件模式与软件模式之间切换时，各自恢复上一次位置、尺寸、锁定状态和滚动/子区上下文；不丢失任务、论文或设置。

## 5. 视觉系统

### 5.1 设计规则

- 默认主题为**雾青蓝**：`base #EAF2F2`、`surface #F8FBFA`、`text #173337`、`accent #246F79`、`success #3B7560`、`warning #A86D31`、`danger #AA514D`。
- 所有主题必须定义同一套语义颜色：应用背景、主表面、次级表面、主文字、次级文字、边线、强调、成功、提醒、警戒、强调色反白。
- 仅主操作和当前选择使用主题强调色；黄色只表示需要关注，红色只表示警戒/删除/逾期，不能作为装饰。
- 不使用渐变背景、透出桌面的默认叠层、发光效果、无意义图标、粗厚阴影或大面积圆角卡片。
- 内容以细分割线、顶部状态线、紧凑栅格替代“卡片堆叠”。边框圆角保持在 4–6 px，阴影最多只用于设置窗和弹窗层级。
- 字体使用 `Microsoft YaHei UI` / `Microsoft YaHei`；采用固定比例（28 / 20 / 16 / 13 / 11 px）和 4 / 8 / 12 / 16 / 24 px 间距节奏。

## 6. 设置体验

设置改为一个统一、可预览的对话框，使用四个可识别的分类，而不是让所有开关连续堆叠：

| 分类 | 内容 |
| --- | --- |
| 外观 | 主题、透明度、界面密度、侧边标签左/右、自动隐藏、固定展开 |
| 窗口与快捷方式 | 小组件/软件模式、置顶、锁定、点击穿透、最小化到托盘、开机自启动、全局显示/隐藏快捷键、期刊导入快捷键 |
| 数据与备份 | 保存路径、自动备份、立即备份、恢复、数据健康检查、文件关联状态 |
| 研究与智能 | DeepSeek 配置、公开数据源、每日前沿更新、研究画像更新、期刊/AI JCR 补全、每日定时与增量更新策略 |

主题选择和透明度在设置打开期间即时预览；点击“保存”才写入配置，点击“取消”必须完全恢复设置打开前的主题与窗口外观。可能导致外部联网或数据恢复的操作保留明确的说明与确认，不在外观页中出现。

## 7. 数据、迁移与兼容

### 7.1 不变的数据文件

`todo.json`、`todo_meta.json`、`papers.json`、`journals.json`、`frontier.json`、`inspiration.json`、`readings.json`、`achievements.json`、`achievement_pdf_cache.json`、`rejection_archive.json`、`reminders.json`、`selection_feedback.json` 及其现有内容必须原样保留。

论文仍为“论文 → `journals[]`”结构；成果 PDF 路径和 PDF 文本缓存仍是现有成果模型的一部分。v10 不能因布局重组而重新保存业务文件、改变日期、清空字段或修改论文/期刊顺序。

### 7.2 设置迁移

`settings.json` 新增、并由 `load_app_settings()` 规范化以下概念：

```json
{
  "ui_mode": "widget",
  "theme_id": "fog_teal",
  "window_profiles": {
    "widget": {"locked": false, "x": null, "y": null, "width": 520, "height": 680},
    "software": {"locked": false, "x": null, "y": null, "width": 1180, "height": 820}
  }
}
```

- 旧 `window` 设置首次加载时迁移为 `window_profiles.widget`。
- 过渡期继续写入与 `window_profiles.widget` 一致的旧 `window` 镜像，保证用户回退到旧程序时仍能恢复小组件位置。
- 缺失/非法主题 ID 回退为 `fog_teal`；未知字段保留，不能删除已有设置。
- 小组件侧边栏设置沿用已有 `sidebar_*` 字段；软件模式不使用标签自动收起，但不修改该偏好。

### 7.3 安装与升级

- 版本号统一升级为 `10.0.0`（应用、PyInstaller、Inno Setup、README）。
- Inno Setup 继续使用 `UsePreviousAppDir=yes`，发布包中排除 `data\*`，所有用户数据设置 `uninsneveruninstall`。
- 默认升级路径必须来自已安装版本的 `InstallLocation`，不能因测试安装或新版本安装创建并行副本。
- 发布前以真实正式安装路径做默认升级测试，比较所有业务 JSON 的 SHA-256；只有程序更新可改变，自动前沿刷新造成的预期数据更新必须单独记录。

## 8. 实施架构

### 8.1 组件边界

- `utils/file_manager.py`：扩展设置规范化、主题 ID、双模式窗口配置和兼容迁移；不改变业务 JSON 保存接口。
- `ui/theme.py`：从单一深色对话框样式升级为主题注册表与语义 QSS 生成入口，同时服务主窗口和所有对话框。
- `ui/main_window.py`：管理模式切换、四个一级入口、几何恢复、托盘、快捷键、自动更新定时器和共享刷新信号。
- 新建软件工作台视图：只负责连续页面和锚点滚动，不直接拥有业务数据；使用既有服务/页面可复用的刷新、编辑、打开对话框接口。
- 现有 Todo、Paper、Notes、Journal、Frontier、Achievements 页面保留其数据操作和对话框逻辑；为小组件四工作台提供轻量容器/适配层，避免把大页面强行 reparent 到软件工作台。
- `ui/settings_dialog.py`：改为四分类设置窗，维护临时预览状态；只有接受时提交到 `file_manager`。

### 8.2 刷新与数据流

1. 用户操作既有业务页/适配区。
2. 既有 `file_manager` 原子写入 JSON，业务页发出 `changed` 信号。
3. 主窗口刷新 HOME、当前工作台、软件工作台对应区段和相关联的服务页。
4. 主题变更仅更新 UI 样式与窗口重绘；不触碰业务数据。
5. 模式切换仅保存/恢复窗口 profile 和可视上下文；不触发业务文件重写。

## 9. 错误处理与可用性约束

- 主题、模式、窗口几何、设置页预览失败时必须回退至安全的雾青蓝小组件状态；不得让窗口不可见、不可移动或无法恢复。
- 保存设置失败时保留旧主题与旧设置，并显示本地、可读的错误提示。
- 所有下拉控件、确认框和编辑框必须在最低 20% 透明度下仍保持高对比、可点击、可读。
- 软件模式在 920 px 宽度下不产生水平滚动条；小组件在 380–540 px 宽度下不发生文本越界、按钮遮挡或卡片裁切。
- 主题切换不重启程序，不中断 DeepSeek/前沿后台任务，不重新读取或保存业务数据。

## 10. 验收与验证

1. 为设置迁移、主题 ID 回退、两套窗口 profile 和保存/取消预览编写自动化测试。
2. 为四工作台的数据归属、HOME 直达、PAPERS 成果/归档动作、LIBRARY 选刊/前沿入口建立行为测试。
3. 运行 `compileall`、现有 `tools/self_check_v097.py`、论文数据安全检查和新增 v10 UI/设置自检。
4. 在离屏环境检查小组件 380 / 460 / 540 px 和软件模式 920 / 1180 / 1366 px 的布局、最小尺寸、无越界与无水平滚动。
5. 使用真实 Windows 窗口完成主题、四工作台、模式切换、托盘最小化、关闭、锁定、点击穿透、位置/尺寸恢复、双击空格快捷键与中文 IME 保护的烟雾测试。
6. 逐一打开期刊编辑、论文编辑、删除确认、设置、归档、成果、研究画像与 AI 错误对话框，验证主题覆盖和文字对比度。
7. 构建正式安装包，并对实际安装目录执行默认路径升级、注册表 `InstallLocation` 与用户数据 SHA-256 审计。

## 11. 不接受的结果

- 把 WORK、PAPERS、LIBRARY 仅改名而没有合并真实入口/上下文。
- 删除、重排序、重新保存或“清理”用户业务数据。
- 在主界面好看但弹窗、下拉、确认框不可读。
- 新安装创建并行数据目录，或升级覆盖现有 `data`。
- 只通过语法检查而未启动真实窗口进行视觉和交互验证。
