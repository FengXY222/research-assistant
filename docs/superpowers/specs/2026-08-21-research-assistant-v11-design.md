# 科研助手 v11.0.0 设计规格

## 1. 目标与边界

v11.0.0 是一次以“科研指挥台”为核心的信息架构与体验升级。它不把科研助手扩展成 Zotero、通用项目管理器或云端知识库；它要让个人科研者能更快完成今天的工作、判断下一步投稿动作、维护可复用的期刊经验，并获得可信、可解释的每日前沿推荐。

本版本保留现有本地 JSON 数据、论文 → `journals[]` 多期刊结构、成果 PDF 链接、拒稿归档、投稿时间线、全局快捷键、桌面小组件、双模式窗口、安装升级与所有既有业务入口。改变的是功能编排、AI 闭环、界面视觉和冗余操作。

本版本不增加账户、云同步、服务端、数据库、自动投稿、自动发送邮件、自动修改论文内容或不经确认的外部写入。

## 2. 已确认的产品决策

1. 正式发布版本直接为 `11.0.0`，不再单独发布 v10。
2. 默认视觉主题为雾青蓝；设置中保留六套主题。视觉规则为不透明表面、弱分割线、紧凑间距、无渐变、无发光、少而明确的强调色。
3. 保持现有窗口比例、侧边标签、首页卡位和使用习惯；七个旧模块不再并列为七个一级页面，而是编入四个工作台：HOME、WORK、PAPERS、LIBRARY。
4. 保留小组件模式和软件模式。小组件模式是无边框桌面便签；软件模式是一张连续滚动的四工作台，不使用明显的页面切换感。
5. AI 只做可解释建议、排序复核、信息补全和可撤销的画像校准；不会静默覆盖用户手填数据、锁定关键词、JCR 核验结果或投稿历史。

## 3. 四工作台与六项补足

| 工作台 | 编排后的内容 | v11 补足 |
| --- | --- | --- |
| HOME | 今日任务摘要、论文状态、最近节点、每日科研简报、灵感、待读 | “今日下一步”聚焦区：最多三项，按截止日、逾期、未完成任务和投稿节点解释排序。 |
| WORK | 今日待办、历史任务、灵感便签、值得阅读 | 统一快速收集入口：将一句文字识别为待办、灵感、待读或候选期刊；保存前必须由用户确认。 |
| PAPERS | 投稿记录、时间线、拒稿归档、成果 | AI 选刊工作台：从候选、比较、准备投稿到投稿历史形成闭环。 |
| LIBRARY | 期刊库、为论文选刊、每日前沿、研究画像 | 期刊库健康检查、每日前沿解释与反馈学习、前沿期刊一键入库。 |

六项补足分别是：今日下一步、统一快速收集、AI 选刊、期刊库健康检查、每日前沿反馈学习、研究画像与质量可信度体系。它们是贯穿四工作台的能力，不新增第五个大型导航模块。

## 4. 双模式应用壳与视觉规则

### 4.1 小组件模式

- 无边框、可拖动、可缩放、可置顶、可透明、可锁定、可点击穿透、最小化到托盘。
- 继续保存位置、尺寸、锁定状态、侧边标签位置和展开状态；收起再展开必须恢复完整窗口几何。
- HOME 保持当前空间关系：顶部轻量栏、边缘竖排标签、上部状态概览、最近节点、下部灵感与待读。
- 每日前沿的研究画像在窄小组件中以“画像”抽屉出现，不压缩文章正文，不新建一级页面。
- 全局显示/隐藏快捷键继续支持双击空格与可自定义组合键；中文输入法处于组合输入状态时禁止双击空格触发。

### 4.2 软件模式

- 使用独立窗口 profile，默认建议尺寸为 1180×820，最小尺寸不低于 920×680。
- HOME、WORK、PAPERS、LIBRARY 位于一张连续 `QScrollArea` 工作台内；顶部锚点只负责定位，不造成多页面切换感。
- 宽窗口采用自然双栏或三栏；窄窗口自动纵向堆叠。必要文字、期刊名、编辑操作和滚动条均不可被裁切。

### 4.3 雾青蓝主题与主题切换

默认主题令牌为：`base #EAF2F2`、`surface #F8FBFA`、`text #173337`、`accent #246F79`、`success #3B7560`、`warning #A86D31`、`danger #AA514D`。

可选主题为：雾青蓝、蓝墨白、苔纸绿、暖砂棕、石墨雾灰、夜读深海。每套主题必须覆盖主窗口、业务页、编辑对话框、删除确认框、下拉菜单、日期控件、滚动条、提示、右键菜单与 AI 错误提示。

设置采用四个分类：外观；窗口与快捷方式；数据与备份；研究与智能。主题与透明度允许实时预览，但只有点击保存才写入设置；取消必须完整恢复预览前状态。

## 5. 研究画像 v11

### 5.1 数据结构与迁移

研究画像不再使用一级、二级关键词分类。新增且规范化为以下概念：

```json
{
  "terms": [
    {
      "id": "stable-id",
      "text": "soil organic carbon",
      "weight": 100,
      "locked": true,
      "source": "user_locked",
      "evidence": ["manual_lock"],
      "updated_at": "2026-08-21"
    }
  ],
  "excluded_terms": ["marine sediment"],
  "filter_known_q3_q4": true,
  "update_log": []
}
```

用户不直接编辑普通研究词的数值权重；AI 根据成果、PDF 文本证据、前沿点击行为和一句话评价决定 `1–99` 的权重。用户可锁定任何词；锁定后权重固定为 `100`，AI 不得降权、删除、改写或移动该词。解锁后才重新交由 AI 校准。

旧 `primary_keywords` 安全迁移为普通研究词，初始权重为 70；旧 `secondary_keywords` 安全迁移为普通研究词，初始权重为 45；旧反馈权重折算进相应词的初始权重与证据。迁移不删除旧字段或任何业务数据；新字段为空时仍可从旧字段回退读取。

### 5.2 画像更新与冲突规则

- 更新证据仅来自用户已有成果、可读取的成果 PDF、前沿按钮行为和一句话评价；不凭空扩展研究方向。
- 同一规范化词或同义词不得同时出现在研究词和排除词中。排除词优先级最高。
- 锁定词永远保留；AI 发现与锁定词冲突时只能写入“待处理冲突”，不能自动替换。
- 证据不足的新词停留在“待确认候选”，不直接参与推荐；自动生效的词必须有可显示的证据摘要。
- 每次有新证据时，AI 重新整理未锁定词的权重、来源和检索短语，并生成可查看、可撤销的变更记录。
- 没有新成果、新 PDF 指纹或新反馈时，源签名不变，禁止调用 AI，避免重复费用。
- 每日自动更新由设置控制；自动更新只能修改未锁定、无冲突的词。发生冲突或低置信度时，改为提示用户审阅。

## 6. 每日前沿 v11

### 6.1 推荐与质量规则

候选文章必须命中至少两个不同研究词；不再以“一级×2 / 一级+二级 / 二级×2”分类抢占排序。所有候选以一个可解释总分直接排序：

```text
总分 = 命中研究词权重之和
     + 期刊优先级（必看 50 / 关注 35 / 扩展 15）
     + 已核验 JCR 加分（Q1 +50 / Q2 +20 / 未知 0）
     + 个人反馈修正（-30 至 +30）
     + AI 复核修正（-15 至 +15）
```

“过滤已知 Q3/Q4 期刊”是研究设置中的开关，默认开启。开启时，已核验为 Q3/Q4、或用户一句话评价明确标记为三四区/低质量的期刊不进入每日推荐；关闭时它们可见但带低分区提示。完全未知分区正常推荐，不额外加减分。AI 的未经核验分区估计只能以“待核验”提示出现，不可作为硬过滤依据。

### 6.2 卡片与反馈交互

每篇前沿卡只显示标题、来源期刊、分区状态、总分和一行“为什么推荐”。详细证据不堆进卡片，按需展开。

固定动作为：不相关、加入待读、标为灵感、一句话评价、加入期刊库。点击“一句话评价”在当前卡片下展开一行输入框，不弹出对话框。评价记录同时保存操作类型、文章、期刊、命中词、当时分数与输入文本。

AI 对评价进行本地可审计分类：主题正向、主题负向、方法/对象偏好、期刊质量反馈、阅读价值等。“这个期刊三四区”只影响该期刊的质量标记和后续过滤，不会错误降低相关研究词的权重。

### 6.3 与期刊库联动

每篇前沿文章显示“加入期刊库”或“已在库”。加入时建立最小期刊记录（名称、可用出版社、首次发现来源、日期），默认每日优先级为“扩展”；重复名称与出版社不得创建第二条记录。期刊库中可继续补全元数据、JCR、方向、个人经验与每日优先级。

## 7. AI 选刊工作台

### 7.1 候选与边界

选刊入口位于 PAPERS 中的具体论文上下文。候选期刊优先来自个人期刊库和用户手动添加的候选；AI 允许提出“待审候选”，但不能自动入库、创建投稿记录或伪造 JCR 数据。

AI 输入仅包含用户点击确认的论文题目、摘要、关键词、研究画像、候选期刊的本地资料与个人经验；不会默认发送成果 PDF 或投稿备注全文。

### 7.2 可解释排序

每个候选显示一个总分和四项可见构成：主题契合（0–40）、质量（0–25）、个人经验（0–20）、投稿约束（0–15）。本地四项相加得到 0–100 分；AI 只给 -10 至 +10 的复核修正，界面必须明确展示“本地分 + AI 修正 = 总分”，不能重复或隐藏计分。AI 不能推翻已核验 JCR、低分区过滤、用户排除、锁定偏好或本地事实。

右侧详情仅展示：为什么适合、四项评分、AI 投稿提示、需要核实的风险、加入投稿路径、加入/跳转期刊库。期刊名在候选列表中优先占用横向空间；操作集中在详情侧，不压缩期刊名称。

“加入投稿路径”才会在该论文的 `journals[]` 中创建一条期刊经历，初始状态为“准备投稿”。它不会影响该论文已有期刊历史，也不会影响其他论文的同名期刊。

### 7.3 失败回退

未配置 DeepSeek、网络失败、JSON 结构无法读取或超时后，仍显示本地规则排序；页面只标示“AI 复核未完成”，不让选刊功能不可用。AI 响应必须使用结构化 JSON、字段白名单、一次安全重试、长度检查和落库前校验。

## 8. 期刊库健康检查

期刊库保持紧凑行式信息：期刊名占主要宽度，出版社与方向标签截断显示，编辑和移动操作集中在行末或更多菜单。出版社按统一的母公司名称分组。

每本期刊增加资料状态：已核验、AI 待核验、资料不全、需要更新、用户低质量标记。健康检查只扫描需要补全或源签名变化的期刊；“全部更新”仅调用尚未更新或已变化的条目，不重复消耗 API。

JCR 的来源必须可见：Clarivate 核验、AI 估计（待核验）、手动录入、未知。AI 估计不得覆盖 Clarivate 核验和用户手动锁定内容。

## 9. HOME、快速收集与低频动作

HOME 新增“今日下一步”，最多三项，说明其排序原因，例如临近回复截止日、逾期修改、今天的高优先待办或需要处理的投稿提醒。它是导航摘要，不创建第二套任务数据。

统一快速收集不是独立页面。它以小型输入框或全局快捷入口出现，先给出待办、灵感、待读、候选期刊四个可修改的分类建议；用户确认后才写入相应现有 JSON 文件。AI 不可在未确认时保存。

低频操作（删除、收藏、导出、资料更新、归档）进入行悬停操作或“更多”，减少首页和列表的长期按钮噪声。删除、归档和恢复继续使用清晰、主题一致、文字可读的确认界面。

## 10. 数据、安装与兼容

`todo.json`、`todo_meta.json`、`papers.json`、`journals.json`、`frontier.json`、`inspiration.json`、`readings.json`、`achievements.json`、`achievement_pdf_cache.json`、`rejection_archive.json`、`reminders.json`、`selection_feedback.json` 及其内容必须保留。

所有 JSON 继续使用原子写入。AI 相关新增字段必须可选、可回退、可迁移，不允许因解析失败清空任何文件。正式安装升级继续使用既有的正式安装路径识别、`UsePreviousAppDir=yes`、排除 `data\*`、`uninsneveruninstall` 与升级前后的数据 SHA-256 审计。

## 11. 验收与两轮自检

### 11.1 自动验证

1. 为研究画像迁移、锁定词、排除词冲突、Q3/Q4 开关、质量反馈解析、前沿去重与总分排序编写测试。
2. 为前沿期刊一键入库、候选去重、AI 选刊本地回退、加入投稿路径和多期刊历史保留编写测试。
3. 为无变化签名不调用 API、新 PDF/新反馈触发一次更新、失败不覆盖用户数据编写测试。
4. 运行 `compileall`、现有数据安全检查、安装升级路径检查、正式数据 SHA-256 审计和新增 v11 自检。

### 11.2 体验自检第一轮：结构与视觉

- 在小组件 380 / 460 / 540 px，软件模式 920 / 1180 / 1366 px 下逐页检查无横向溢出、无文字截断、无巨大空白、无按钮遮挡、无低对比下拉框和无错误色块。
- 逐一检查 HOME、WORK、PAPERS、LIBRARY、研究画像、选刊、期刊编辑、论文编辑、删除确认、归档、成果和设置。
- 验证主题切换、透明度、标签左/右、标签隐藏、窗口锁定、点击穿透、托盘、最小化与全局快捷键。

### 11.3 体验自检第二轮：真实流程

- 以现有正式数据启动，完成一条前沿评价、一键导入期刊、画像更新、期刊筛选、选刊、加入投稿路径、改状态、拒稿归档和成果转移。
- 验证未知分区正常推荐；已知 Q3/Q4 在默认设置下被隐藏；关闭开关后可显示；一句话“三四区”只改变期刊质量处理。
- 验证新旧安装包默认路径升级不新建并行数据目录，用户数据、PDF 链接和窗口设置均不丢失。

## 12. 不接受的结果

- 再次把所有功能并列成大量一级标签，或新增一个“AI”大模块。
- 用 AI 猜测值伪装成 JCR 核验结果，或让 AI 静默覆盖手动内容。
- 继续按关键词组合类别而非总分排序每日前沿。
- 把用户的“三四区”评价误判为研究主题不相关。
- 仅让宽窗口好看，窄小组件、弹窗、下拉菜单或删除确认框不可读。
- 升级创建平行安装/数据目录，或使已有 JSON、PDF 路径、论文期刊经历丢失。
