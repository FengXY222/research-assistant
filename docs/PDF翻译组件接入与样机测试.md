# 独立 PDF 翻译组件：接入与实际测试

测试日期：2026-10-01。此次修改为源码接入和独立组件测试，没有重新打包、自动安装主程序或上传 GitHub。原有未提交改动保留。

## 已落实的规则

- 侧栏“文献”下方新增“工具”，导航到“工作 → 工具 → PDF 翻译”，所有导航经过主窗口。
- 单独 Python 3.12 环境；主程序仅加载轻量界面、SQLite 队列和 QProcess 控制器，不导入 PDF 翻译引擎。
- 一次一篇，其他按加入时间排队；默认并发 2、独立 QPS 2；主软件每秒 5 次请求限制、AI 启用开关和空闲任务取消均不作用于它。
- 点击取消先发送指令，通知异步任务 `cancel()` 与内核停止；6 秒后未退出则清理任务自己的进程树。普通鼠标操作、页面切换不取消手动翻译。
- 保存参数及中断状态，重试复用 next 的译文缓存。重启不自动重试，需手动继续；这不是逐页精确续传。
- 进度事件间隔 0.5 秒；模型和字体按需加载；worker 及辅助进程结束后退出。
- 输出放入任务专属目录，不覆盖输入；密钥用 DPAPI 保存，任务快照不保存密钥。

## 真实场景发现的问题及处理

1. next 高层异步接口内部另起的 Windows multiprocessing 子进程持续停留在启动状态，未返回进度。最终采用固定版本的 next 配置适配器 + BabelDOC 异步内核，由外层独立 worker 负责隔离。
2. 字体压缩和 PDF 保存阶段也受同样启动问题影响，分别等待 60/120 秒才回退。已改为显式启动的轻量辅助进程，保留超时和进程树归属，最终测试正常通过。
3. 默认术语抽取额外处理全篇段落。已关闭自动抽取；正文翻译保留。805 个段落的进度计数不等于 805 次 API 调用：短文本、数字及缓存命中不会都产生请求。
4. DeepSeek 思考模式可能拉长段落翻译响应，官方地址单独关闭思考模式，其他服务不强行发送此参数。参考：[DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
5. 组件只限定翻译并发仍不足以限制 ONNX 的内部线程，因此另将 ONNX 推理线程设为 2、OpenCV 线程设为 2。

## 输出检查及已知限制

用 Poppler 渲染中文 15 页和双语 15 页，并检查全部页面的整体布局；主要段落、世界地图、曲线图和表格仍可阅读。未进行全文逐句翻译准确性或逐公式校验。

仍有少量英文标题、短文本混排及复杂表头不够理想，例如 SUMMARY 标题与部分 Validation metrics 文本；复杂表格/公式需对照原文核查。Poppler 提示缺少 Symbol/ArialUnicode 的替代显示字体，目视未见整页空白，但不能据此保证每个特殊符号完全一致。原文保留在双语版，建议以双语版核对。

低并发不能消除版式模型、字体及 PDF 中间结构的内存开销，全文样机仍约 3.23 GiB；隔离避免主界面跟着膨胀，结束后归还内存。内存较小的电脑应谨慎安排翻译任务。

当前开发机器已安装组件 venv；发行包只收集轻量宿主和 worker，未给未安装 Python 的电脑制作便携组件运行包。部署说明和依赖锁位于 `components/pdf_translator/README.md` 与 `requirements.lock`。上游声明 AGPL-3.0，发布前需要保留许可、来源与对应源码信息。
