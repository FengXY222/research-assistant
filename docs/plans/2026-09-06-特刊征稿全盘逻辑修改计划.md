# 特刊征稿全盘逻辑修改计划

日期：2026-09-06  
基线：科研助手 v12.1.3  
状态：待实施。本次仅编写计划，不修改程序、正式数据、版本号或安装包。  
依据：[特刊逻辑审查及 10 项复现记录](<S:/小软件/docs/特刊逻辑审查-20260906.md>)、当前源码和此前已确认的需求。

## 1. 目标与边界

把特刊征稿变成可信、相关、可操作的个人科研信息流：找到真实征稿，识别是否仍开放，根据综合研究方向及具体论文判断适配程度，并可靠保存收藏、关联、投稿路径和准备任务。

本计划覆盖“画像输入 → 多源发现 → 去重 → 征稿正文 → 期刊身份与事实 → 开放状态 → AI 匹配 → 筛选排序 → 展示操作 → 刷新提醒”的完整流程。共享画像、期刊库、每日前沿只调整必要的接口和研究边界复用，不进行无关重写。

### 1.1 保持不变的产品决定

- 只保留小组件模式；不新增 SUBMIT 顶层导航。
- 特刊征稿仍位于 LIBRARY，与每日前沿、期刊库并列；每日前沿仍为默认页。
- 小组件展示符合条件及已收藏特刊、最高匹配、最近截止日期和未读数量；详细操作进入独立 1024×768 工作台。
- 为论文选刊仍从 PAPERS 快捷入口打开独立大界面，本计划不重新设计选刊界面。
- 收录 Special Issue、Topical Collection、Research Topic、Article Collection；排除会议、Workshop、图书章节、普通期刊常年征稿和仅邀请投稿。
- 支持综合研究画像与每篇论文的特刊画像。同一特刊显示一张卡片，列出所有达到匹配线的关联论文。
- 未知出版社、费用、分区等仍可在筛选结果末尾显示；不能把“未知”当成“已知不符合”。
- 聚合站内容足够新、有有效截止日期时可以正式推送，但必须醒目标为“未官网核验”。
- Elsevier、Springer Nature、Taylor & Francis、Wiley 优先；其他出版社降低排序优先级，不整类淘汰。
- 收藏、忽略、关联论文、入库、加入投稿路径、创建任务之后，工作台保持打开。
- 兼容 10.0 及之后数据；分阶段验收，最终只安装一个正式版本，不安装中间版本。

### 1.2 这次不做什么

- 不清空特刊、关键词、论文、期刊库或每日前沿历史。
- 不因为当前推荐为零就取消相关性门槛、伪造分区或填充无关征稿。
- 不将“每日前沿的 JCR 1/2 区规则”自动套用为特刊默认规则；特刊按自己的筛选条件处理。
- 不迁移整个应用到新数据库，不引入独立服务器，不依赖 Computer Use 验收。
- 不把抓取失败解释成官网关闭，不把 AI 推测解释成已核验事实。

## 2. 当前问题与处理原则

审查时缓存为 36 条，正式推荐为 0。这个结果不能证明没有合适特刊，也不能说明 36 条都应该推荐。已确认的逻辑问题如下，编号与审查报告对应。

| 编号 | 当前问题 | 计划中的修正原则 | 实施阶段 |
| --- | --- | --- | --- |
| 1 | 后台刷新覆盖收藏等个人操作 | 外部信息与个人状态分开管理，提交时合并最新个人状态 | 一 |
| 2 | 相似期刊名称导致不同 ISSN 借用分区 | 先确认身份；模糊名称只发现候选，不直接继承事实 | 二 |
| 3 | 已关闭征稿仍以旧高分推荐 | 开放资格独立于匹配分，小组件、工作台、通知共用规则 | 二、五 |
| 4 | 过期后不再访问官网，延期无法恢复 | 保存日期证据和历史，允许可信的新开放状态重新生效 | 二 |
| 5 | 其他出版社减半后永远低于准入线 | 内容准入用 AI 原始匹配分；出版社只影响排序 | 三 |
| 6 | 聚合页冒充官网、抓取时间冒充内容新鲜度 | 分开发现链接、官方链接、原始更新时间和抓取时间 | 二 |
| 7 | 候选数量上限清掉已关联、已建任务的记录 | 数量上限仅限制单批处理，不限制个人历史保留 | 一、四 |
| 8 | 字面排除误伤矿物保护、土壤健康等方向 | 共用情境化研究边界，隐藏阻止名单不参与科学内容排除 | 三 |
| 9 | 指定论文仍显示综合画像的高分 | 独立保存并使用该论文的评分、理由和合格状态 | 三、五 |
| 10 | 所有来源失败仍记作刷新成功，延误重试 | 按来源记录成功、失败和重试时间，整体状态允许部分成功 | 四 |

采用“现有结构上做有边界的调整”：保留 JSON 正式数据，复用现有 SQLite 证据缓存，加强存储提交和统一判定。仅零散修改上述条件不足以解决多处规则不一致；全量数据库重写则超出这次必要范围。

## 3. 新的完整流程

```text
读取最新画像与论文快照
  → 生成按研究方向分组的检索任务
  → 多来源发现，保留来源证据
  → 识别征稿类型，建立稳定 ID，合并确定重复项
  → 提取完整征稿正文，保留原文，自动翻译
  → 核对期刊身份、出版社及分区等事实
  → 判断开放状态、截止日期和来源可信程度
  → AI 分别评估综合画像与每篇论文的适配性
  → 内容准入，再应用用户筛选，最后计算排序优先级
  → 合并最新个人状态后提交结果
  → 小组件、工作台和通知读取同一判定结果
  → 后续刷新更新日期、状态和证据，不覆盖个人操作
```

每一阶段均记录输入版本、处理结果、失败原因和数量。没有合格结果时显示真实原因，例如“来源失败”“正文不足”“不相关”“已关闭”“筛选不符”，不能只显示笼统的“没有结果”。

## 4. 数据与状态模型

### 4.1 将四类状态分开

| 维度 | 保存内容 | 更新权限 |
| --- | --- | --- |
| 征稿事实 | 名称、期刊、来源、正文、出版社、费用、日期及对应证据 | 来源适配器和核验服务 |
| 生命周期 | 开放、关闭、过期、未知；每次变化的依据与时间 | 状态判定服务 |
| 核验状态 | 官网已核验、聚合来源未官网核验、暂时无法访问、身份或事实冲突 | 核验服务 |
| 个人状态 | 已读时间、是否收藏、是否忽略、关联论文、任务及投稿路径引用 | 用户操作服务 |
| 匹配结果 | 综合及逐论文分数、理由、证据、研究分支、版本、是否过期 | 匹配服务 |

“收藏”和“已读”不再互相替代。一条征稿可以已读且收藏，也可以已过期但仍收藏。忽略不删除历史；恢复后重新参与当前条件判断。

### 4.2 稳定身份与去重

1. 优先使用来源内稳定征稿 ID、已确认官方 URL、期刊身份及特刊标题建立身份。
2. 截止日期、AI 分数、列表顺序不得参与稳定 ID；延期和重新排序不能变成新征稿。
3. URL 仅删除已知追踪参数，保留影响征稿身份的查询参数；保留重定向前后链接及依据。
4. 跨来源合并要求可靠身份依据。近似标题只能标记“可能重复”，不能自动合并两个不同专题。
5. 合并保留来源列表、日期历史和全部个人引用；旧 ID 到新 ID 的别名表持久保存，不能只放在可重建缓存里。
6. 相同专题的新一届、另一轮独立征稿不因名称相同直接覆盖；结合来源 ID、期次和官方证据区分。

### 4.3 写入与并发

- 后台联网和 AI 工作只产出外部信息补丁，不携带有权覆盖个人状态的旧快照。
- 正式提交经过统一的串行写入入口，重新读取最新记录，再按字段归属合并。
- 使用记录版本防止旧任务覆盖新事实；画像或正文版本变化时，旧评分标为待重评，不提升为最新有效推荐。
- 入库、投稿路径、准备任务等跨文件操作使用明确事务记录和幂等键。单个文件原子替换不等于多文件原子提交。
- 复用并增强 `action_transaction.py`，加入提交清单、异常恢复和启动恢复；未完成恢复前保留备份，不静默丢弃回滚失败。
- 进程内串行队列与文件写入锁协调，避免后台、界面和其他写入入口同时读旧值再覆盖。
- 个人状态、ID 别名、引用及通知待发送记录属于正式数据；来源响应和 AI 证据缓存可重建。

## 5. 发现、正文与核验规则

### 5.1 多源发现

- 将出版社官网、聚合站分成独立来源，分别记录上次成功时间、错误和本批结果。
- 四个优先出版社均有独立的发现机会；不能由一个来源先占满配额，其他来源没有进入匹配阶段的机会。
- 检索覆盖核心方向、每篇论文以及已确认探索方向，不只截取固定前几个关键词。
- 单批预算按来源和研究分支轮转；收藏、已关联和临近截止项的状态检查优先，但不无限挤占新征稿发现。
- 对 Elsevier、Springer Nature、Taylor & Francis、Wiley 分别检查列表解析、分页、详情链接和专题名称别称，保存离线页面样本。
- 公开项目只在确有帮助时复用，并记录来源和许可证；没有许可证不能因“自用”就默认取得复制、再分发许可，可参考公开行为自行实现。
- 尊重访问限制、频率限制与服务条款，不绕过登录或反爬限制；来源不可访问时保留其他来源结果并明示缺口。
- 本计划不声称当前外部站点均在线可用；实施时对各来源做小规模真实连接验证。

### 5.2 正文提取与自动翻译

1. 优先提取征稿范围、主题列表、投稿要求、截止日期等正文区域，去除脚本、样式、导航、广告和重复页脚。
2. 保存原始响应摘要、正文版本、段落 ID、正文语言和抓取时间；不能把 CSS/JavaScript 当成完整征稿范围。
3. 只有列表标题或短摘要时进入“正文待补”，不宣称已阅读完整范围，不进入基于完整范围的正式 AI 推荐。
4. 长正文按段落分段处理，保留跨段合并结果和覆盖记录；禁止只读第一段却声称覆盖完整正文。
5. 复用内置开源翻译服务，自动翻译征稿正文与需要展示的关键词；原文可展开，译文失败保留原文并显示实际状态。
6. 译文用于阅读，不覆盖英文原名、ISSN、日期或来源证据。专业缩写保留原词，允许编辑中文翻译但不改锁定关键词本体。
7. 从网页取到的文字视为数据；AI 不执行网页中的指令，不使用网页内容修改画像权限或个人数据。

### 5.3 期刊身份与出版社

- 规范化 ISSN，并在可用时检查校验位。印刷 ISSN、电子 ISSN 可以不同，只有可靠来源确认同属同一期刊或同一 ISSN-L 才能归并。
- 没有证明不同 ISSN 属于同刊时，不能靠相似名称继承期刊库分区。明确冲突进入待处理区；单纯缺少 ISSN 则保留未知状态。
- 名称模糊匹配用于寻找核验对象，不直接授予“身份已确认”。名称相近不等于同刊。
- 出版社采用规范名称、已核实品牌归属、官方域名和期刊身份信息综合识别，保留原始值和来源。
- Crossref 注册机构、学协会所有者、出版平台与实际出版社不一定是同一字段，不因单个机构名称差异强行覆盖。
- 四个优先出版社维护可核对的别名与品牌映射，遇到新品牌进入待核验，不靠标题中出现出版社名称直接确认。
- 官方域名检查使用域名边界和可信身份来源；不能用字符串包含判断，不能将聚合域名当官网。

### 5.4 JCR、中科院与费用

- 已配置 EasyScholar 时按确认的期刊身份请求分区，保存查询名、命中期刊、分区版本、来源和更新时间。
- 本地期刊库有可靠同刊事实时可以补充；信息冲突需显示出处和待核验状态，不能挑一个更好的分区通过筛选。
- 未配置或请求失败时保留已有可靠信息；未知就显示未知，不制造默认 Q1，也不借用相似期刊的信息。
- 已知分区、出版社等不符合当前筛选时，从当前推荐结果隐藏；未知值仍保留在末尾并注明未确认满足条件。
- Hybrid 同时符合“付费”和“不付费”筛选；费用未知置后。“不付费”只代表存在非 OA 投稿路线，不保证没有其他可能费用。
- 截止时间与费用均不由 AI 猜测补齐。预计处理速度有来源才显示区间与时间，没有就显示暂无可靠数据。
- 期刊库入库保存证据及来源；刷新不覆盖用户手填值，外部不一致信息独立保存供复核。

### 5.5 开放状态与聚合站

正式推荐需要：属于收录类型、身份不存在明确冲突、正文足够、相关性合格，并满足以下一种开放依据。

| 情况 | 处理 |
| --- | --- |
| 官网确认开放，截止日期未过 | 可推荐，展示官网核验日期 |
| 新鲜聚合内容、未来截止日期，官网未确认 | 可推荐，醒目标记“未官网核验”，每天继续核验 |
| 聚合内容发布时间未知或过旧 | 保留在待核验，不以本次抓取时间冒充新鲜度 |
| 官网确认关闭，即使名义截止日期未到 | 停止开放推荐和新征稿通知，保留收藏及历史 |
| 截止日期已过 | 从开放推荐移出，继续按条件检查延期，不永久冻结 |
| 请求超时、403、429 或解析失败 | 记为访问/解析失败，不判定关闭；旧事实附时效状态 |
| 日期、身份或官方开放状态有明确冲突 | 进入待核验，不依靠旧高分继续推荐 |

官网没有明确日期但确认专题开放时保留在待核验列表，截止筛选置后；在获得明确期限或用户明确改变收录规则前，不伪造倒计时。

较新的可靠延期证据可以更新截止日期；旧日期保留在历史。已确认关闭只能由新的可靠开放证据恢复，不能被一次抓取失败或旧聚合页恢复。新增日期证据到达时立即重新核验，不因旧日期已过跳过。

## 6. 研究画像与 AI 匹配

### 6.1 共用研究边界，不复制每日前沿全部门槛

| 主题情境 | 特刊处理 |
| --- | --- |
| 土壤碳矿物保护、矿物结合碳、碳铁结合 | 保留为相关方向，不因 mineral 被字面排除 |
| 纯矿物结构、合成、晶体等，无土壤碳或已确认研究目标 | 不进入相关推荐 |
| 土壤肥力、土壤健康、土壤质量指数评价 | 可以推荐，不强制要求 SOC |
| 明确服务滑坡评价的 DEM、地形或水文方法 | 进入低优先级探索，不因没有 SOC 拒绝 |
| 泛医学、纯化学、纯生物学且与研究目的无实质联系 | 不因共享 carbon、model、prediction 等词进入推荐 |
| 一段征稿范围同时列出相关与不相关方向 | 判断是否存在明确可投稿的相关分支，不被任意一个不相关词一票否决 |

复用共享的“研究对象、研究目的、允许分支、排除情境”定义，特刊独立判断征稿包容范围。每日前沿的论文准入线和核心/探索比例不直接移植到特刊。

### 6.2 画像来源及权重

- 已有论文、锁定关键词是长期强信号，不衰减；每篇论文保留独立主题，不能被综合画像中的主方向完全覆盖。
- 收藏、关联论文是强正样本；打开详情和已读是弱正样本；明确忽略为强负样本；无操作不产生负样本。
- 一句话评价实时更新相关画像；其他行为每日整理。解释其对象范围，避免“这篇不需要”变成全学科永久排除。
- AI 可按现有授权整理普通词和排除词，但不能修改锁定词、恢复手动删除词；整理失败保留原画像，成功前保留最近一次可撤销快照。
- `blocked_terms` 只阻止被手动删除的词重新进入关键词库，不作为论文或特刊内容排除词。
- 历史 `mineral`、`soil health` 等宽泛排除与新确认边界冲突时，在迁移预览中明确列出；不在本次计划中擅自删除正式词条。
- 综合画像与论文画像均带稳定版本；只把语义内容放入匹配缓存键，不能将每次变化的生成时间加入缓存键导致无效重算。

### 6.3 匹配输出合同

AI 每次必须返回可验证的结构化结果：综合匹配分、推荐理由、所匹配研究分支、相关征稿段落、风险或不匹配点，以及逐论文的独立匹配分和理由。

AI 负责理解内容，不负责编造出版社、分区、截止日期或官网认证。服务端检查分数范围、段落引用和论文 ID；输出格式错误、缺少关键证据或 AI 超时则保留待评估，不自动以关键词数量代替正式 AI 高分。

同一排除情境仅判断一次。不能让 AI 已扣分后又按每个词重复扣分；也不能让否定表达或偶然提及产生内容淘汰。存在相关子方向时，应说明该论文适合专题的哪一部分。

### 6.4 准入与排序分开

建议沿用当前内容合格线 60 分、高匹配通知线 80 分，先用标注样例复核，不将这两个数声称为统计校准后的概率。

```text
内容合格 = 有足够正文证据 且 AI 匹配分 >= 60 且 不属于明确不相关情境
开放推荐资格 = 内容合格 且 开放依据有效 且 无明确身份/事实冲突
当前展示 = 开放推荐资格 且 未被忽略 且 不存在已知筛选不符

排序基础分 = AI 匹配分 × 出版社排序权重
四个优先出版社：1.0；确认属于其他出版社：0.5
出版社或筛选事实未知：归入结果末尾，不伪装成已满足条件
```

卡片显示 AI 原始匹配分和理由；出版社降权在核验依据中说明，不把排序分冒充 AI 总分。探索分支默认排在合格核心方向之后；同组内按排序基础分排序，再用费用偏好、可核实速度及有效截止日期作次级排序，不让临近截止把不相关专题推上来。

非四个优先出版社的 90 分特刊仍可通过内容准入，只是排序基础分为 45。未知信息置后与“正文不足”“期刊身份冲突”不同，后两者不得混进正式推荐。

### 6.5 综合视图与指定论文视图

- 综合视图使用综合画像分数；具体论文视图必须使用该论文分数、理由、内容准入状态。
- 同一特刊综合 95 分、论文 A 5 分时，不得在论文 A 的推荐里显示 95 分。
- `matched_papers` 只列达到论文合格线的论文；低分结果可留在证据中，但不冒充适配关联。
- 有指定论文的合格结果但综合分低时，仍可在该论文视图和“适合你的某篇论文”入口发现；不以综合分将其永久删去。
- 未完成某篇论文评估时显示待评估，不借用综合分。用户仍可明确手动关联，但关联操作本身不伪造匹配分。
- 旧评分只有在正文、画像、匹配政策均未变化时可复用；旧算法分数不能直接除以出版社系数来恢复，因为可能已经混入字面排除扣分。

## 7. 操作、数据保留与提醒

### 7.1 操作合同

| 操作 | 唯一直接效果 | 防误操作要求 |
| --- | --- | --- |
| 收藏/取消收藏 | 修改收藏状态，保留已读及关联 | 后台刷新不得覆盖；重复点击不产生重复条目 |
| 已读 | 写入已读时间并更新未读计数 | 不取消收藏，不跳到列表后部 |
| 忽略/恢复 | 修改个人忽略状态并记录行为信号 | 不物理删除征稿及已有引用 |
| 关联论文 | 仅建立特刊与论文关联 | 不自动入库、建任务或加入路径 |
| 加入期刊库 | 复用已确认同刊或创建待补期刊 | 身份冲突不自动合并；重复执行不重复入库 |
| 加入投稿路径 | 必要时快速入库，再创建包含特刊 ID、名称、截止日期的候选 | 使用当前行及当前论文 ID，不使用列表第一项；跨文件一起成功或恢复 |
| 创建准备任务 | 单独建立任务，关联论文、特刊及有效截止日期 | 有现有任务时定位或复用，不无提示重复创建 |

已拒稿或该论文手动排除的期刊：不自动加入该论文的路径，明确说明冲突；保留查看和收藏，不将一篇论文的拒稿扩大成全局期刊封禁。用户主动要求再次加入时进行明确确认，记录例外。

日期延期自动更新征稿事实和路径中的特刊截止信息；用户手动设定的任务日期不静默覆盖。任务保留“跟随特刊截止/独立日期”的来源属性，独立日期在变更提醒中供用户决定。

已关闭、已过期的征稿保留收藏和历史引用，但不能以开放征稿名义新增投稿路径或截止准备任务；可继续查看、入库及管理已有关系。

### 7.2 保留政策

- 当前 36 条上限改为单批处理预算，不再作为永久存储容量。
- 收藏、忽略、已读、关联论文、投稿路径、任务或未处理通知所引用的记录不得因新结果增多消失。
- 普通未操作的旧缓存可转入可查询历史，但不在本次更新中物理清理；将来清理需独立规则和可恢复备份。
- 去重、记录重命名或来源切换后，所有引用可继续解析；不产生悬空任务或无来源候选。

### 7.3 刷新与进度

- 启动时按来源判断距上次有效检查是否超过 24 小时；手动刷新随时可用，已有刷新运行时复用进度而非重复启动。
- 应用持续运行时定期检查是否到期；应用关闭时不声称后台仍在采集。
- 分别保存 `last_attempt_at`、`last_success_at`、`next_retry_at`、失败类型和已完成阶段。
- 所有来源失败：整体失败，保留旧结果，不推进成功时间。部分成功：保存成功来源，明确显示失败来源并独立重试。
- “成功但没有新结果”和“失败”分开；网络、翻译、AI 某阶段失败不否定已成功取得的其他证据。
- 进度展示真实阶段、完成来源数、处理条数、缓存命中及重试状态；未知耗时用忙碌状态，不用虚假百分比长期停在 99%。
- 取消刷新停止派发新任务，保留已完成的安全结果和个人操作；最终提交后才能显示完成。
- AI 匹配使用独立功能配置或清晰兼容配置，不因关闭画像自动整理而无意禁用手动特刊匹配。

### 7.4 通知

- 仅新出现、达到高匹配线且当前具有开放资格的征稿触发新推荐通知；已读/已忽略不反复通知。
- 收藏后在截止前 90、60、30、14、7、3 天提醒。错过多档时只补发最近一个仍有意义的节点，避免启动时连续弹出所有过期节点。
- 日期变化和征稿关闭单独生成事件；关闭后不再发送“快截止、仍可投”的提醒。
- 延期改变提醒基准，保留旧日期历史；按特刊 ID、日期版本、提醒类型去重。
- 先写待发送事件，再交给通知服务；实际交付成功后才记作已发送。桌面通知被调用成功不等于用户已读。
- 超过单批弹窗限制的事件进入摘要及站内未读列表，不因只显示前几条就将全部标为已通知。
- 特刊通知不复用每日前沿的状态字段，两个信息流的已读和忽略互不影响。

## 8. 界面所需的统一逻辑

- 小组件和大工作台调用同一个列表判定入口，不再各自用 `formal` 或单独的分数阈值猜测能否推荐。
- 工作台保留推荐、收藏、待核验、状态变化入口；推荐中允许符合规定的聚合站条目，但展示未官网核验标识。待核验可包含这些仍待官网确认的条目及暂未具备准入资格的条目，并区分原因。
- 收藏视图即使条目过期或不再满足研究偏好也可查看，并清楚展示当前状态，不自动取消收藏。
- 出版社、费用、JCR、中科院、截止筛选作用于当前列表，不重跑网络请求、不删除缓存；未知项统一置后。
- 左侧列表为期刊名、专题名、状态和分区提供可读宽度；长名换行或省略配完整提示，不挤掉导航标签。
- 右侧征稿正文独立滚动，推荐理由、全文译文、核验依据和操作区互不遮挡；期刊名可直接选择复制。
- 列表选择、滚动位置和展开项按稳定 ID 保持。收藏、入库、已读等完成后不重新选中第一条、不跳到列表末尾。
- 空状态分别显示暂无合格、筛选后为空、待评估或请求失败；可以查看处理数量及原因，不笼统归因 AI 不推荐。
- 操作失败保留输入、选中论文和工作台，显示可以重试的具体原因；按钮忙碌期间防重复提交。

## 9. 建议默认参数

以下为实施起点，不是用户已经逐项确认的数值。通过样例验收后固定，并集中配置，避免散落在多个模块。

| 参数 | 建议值 | 原因与限制 |
| --- | --- | --- |
| 内容准入线/新征稿通知线 | 60 / 80 | 延续现有尺度，结合固定样例评估误推和漏推 |
| 其他已知出版社排序权重 | 0.5 | 落实降权偏好，不改变内容准入 |
| 单批新候选深入处理预算 | 36 | 控制请求与 AI 成本，剩余任务轮转，不删记录 |
| 启动及运行中到期检查 | 超过 24 小时刷新；运行中每小时检查到期 | 防止只能重启才更新 |
| 聚合内容新鲜度 | 来源可确认发布/更新时间距今不超过 7 天 | 时间未知或过旧进入待核验，抓取时间不替代内容时间 |
| 官网开放证据有效期 | 通常 24 小时；截止前 14 天缩短为 6 小时 | 超期未核验显示状态待更新，不能无限沿用开放标签 |
| 已过期/关闭的收藏或关联项复查 | 最长每 7 天；新延期证据出现立即检查 | 避免永久错过延期，同时控制访问成本 |
| 分区等期刊事实缓存 | 30 天；手动强制刷新可绕过 | 显示数据年份与缓存时间，过期事实不能伪装最新 |
| 来源故障重试 | 15 分钟、1 小时、6 小时退避 | 遵守服务端 Retry-After，不推迟 24 小时才重试 |
| 单次网络调用重试 | 含首次最多 3 次 | 超限保留状态，允许后续调度重试 |
| 同输入 AI 失败重试 | 每批最多补试 1 次 | 不因输出无效造成无限收费循环 |

超过有效期的旧开放证据不从个人收藏消失，但推荐/通知需重新获得有效开放依据。存在新鲜聚合证据时可按未官网核验规则继续展示，不能继续挂旧的“官网已核验”标签。

## 10. 分阶段实施任务

顺序为一 → 二 → 三 → 四 → 五 → 六。每阶段先补能复现问题的测试，再修改对应范围，通过数据与界面合同检查后进入下一阶段。过程中不覆盖安装正式程序。

### 阶段一：保护个人数据和引用

修改范围：`utils/special_issue_repository.py`、`utils/action_transaction.py`、`utils/special_issue_service.py` 的提交部分。测试落在 `tests/test_v12_special_issue_repository.py`、`tests/test_v12_special_issue_actions.py`，并新增事务恢复专项测试。

1. 明确字段归属，升级存储结构并保留旧字段的迁移来源，确保归一化函数不会丢弃新增字段。
2. 实现稳定 ID、持久别名、个人状态独立合并、版本检查和串行写入。
3. 将刷新整体覆盖改为事实补丁提交；将记录容量上限改为处理预算。
4. 对入库、路径和任务操作增加幂等键、跨文件提交与崩溃恢复记录。
5. 测试刷新中收藏、取消收藏、忽略、关联和创建任务；测试重复点击、写入失败及提交中断恢复。

验收：所有个人操作在刷新后保留；重启后引用仍完整；一个动作不出现半完成状态；超过候选预算不丢历史。

### 阶段二：建立可靠身份和开放状态

修改范围：`utils/special_issue_sources.py`、`utils/special_issue_service.py`、`utils/publisher_utils.py`、`utils/journal_quality.py`、`utils/easyscholar_service.py`、`utils/local_translation.py`。公共工具只做必要的兼容增强。

1. 分离来源 URL 和官网 URL，保存原始时间、抓取时间及正文段落证据。
2. 收紧身份匹配，支持已证实的印刷/电子 ISSN 归并，拦截明确不同期刊借用事实。
3. 建立开放、关闭、过期、未知的独立判定和日期历史；让延期能够重新核验。
4. 统一聚合来源准入与官网标识；修复正文污染、翻译失败回退和日期冲突处理。
5. 为四个优先出版社建立离线解析样例、名称别名与来源覆盖报告。

验收：不同刊不串分区；聚合页不能升级官网；关闭记录不推荐；延期恢复可追踪；正文无样式代码污染。

### 阶段三：重做匹配准入与排序

修改范围：`utils/special_issue_matching.py`、`utils/ai_service.py`、`utils/research_signal_service.py` 及共享研究边界接口。可新增 `utils/research_scope_policy.py` 作为最小共享定义，保持 `utils/frontier_admission.py` 原有调用兼容，不整体迁移每日前沿算法。

1. 区分隐藏阻止名单与内容排除；以情境边界替代单词出现即扣分。
2. 综合和逐论文独立评估，验证 AI 证据引用、论文 ID 和结果结构。
3. 分开内容分、准入状态、出版社排序权重及未知信息分组。
4. 增加稳定版本和缓存键；画像改变、正文改变或规则改变时使相关评分失效。
5. 建立覆盖核心、允许边界、低权重探索和无关学科的固定人工标注样例。

验收：矿物保护和土壤健康不被旧词误伤；纯矿物学不混入；滑坡方法不因缺 SOC 被拒；其他出版社可以内容合格；指定论文不再借综合分。

### 阶段四：调度、缓存和通知可靠性

修改范围：`utils/special_issue_service.py`、`utils/evidence_cache.py`、`utils/submission_reminders.py`、`ui/main_window.py`。正式个人信息不迁入可销毁证据缓存。

1. 来源独立检查点、处理队列、失败重试和部分成功状态。
2. 为收藏及关联项安排日期核验，新发现按来源与研究分支公平轮转。
3. 实现进度、取消、超时以及旧证据的有效期状态；请求和 AI 都不阻塞界面线程。
4. 建立待发送通知记录、发送确认、摘要与过期提醒补发规则。
5. 记录每阶段数量、耗时、错误分类和缓存命中，日志不保存密钥或不必要的完整论文内容。

验收：全失败不改成功时间；部分成功可使用；过期/关闭无新征稿通知；日期变更和漏过提醒不重复、不丢失。

### 阶段五：统一界面行为

修改范围：`ui/special_issue_page.py`、`ui/special_issue_dialog.py`、`ui/main_window.py`，必要的主题样式文件；不新增顶层导航。

1. 小组件、工作台、通知共用统一准入与视图过滤结果。
2. 区分综合和论文视图，显示当前视角的分数、理由、未知状态与适配论文。
3. 所有操作绑定稳定记录 ID 和论文 ID，保留选中项、滚动位置及打开状态。
4. 修正长标题、期刊名、页签、正文滚动、操作区和繁体/中文字体缩放下的布局。
5. 使用 Qt 自动化、离屏截图和控件几何检查覆盖 1024×768 工作台、小组件实际尺寸及 100%/125%/150% 缩放；不调用 Computer Use。

验收：所有主要控件可见可点；长文本不遮挡；小组件与工作台同条件数量一致；操作不关闭、不跳页、不错选第一条。

### 阶段六：离线对照、迁移与最终发布

修改范围：迁移与离线验证脚本、相关测试、发布说明；只有通过验收后才更新版本和打包配置。

1. 将正式数据复制到隔离目录，建立旧逻辑/新逻辑影子对照，正式数据不参与测试写入。
2. 对旧分数、错误身份继承和过时官方标签标记待重评；不尝试数学反推原始 AI 分，不一键信任旧核验。
3. 输出新增推荐、移出推荐、待核验及原因，逐项核对用户明确保留和排除的主题样例。
4. 所有离线用例通过后，小规模验证真实来源、EasyScholar、翻译和 AI；真实调用失败需如实列出，不用缓存通过冒充在线通过。
5. 用户确认结果后，确定正式版本号、构建一个安装包，执行安装启动、核心操作、Qt DLL 和数据保护检查。
6. 最终输出测试报告、数据迁移差异、文件哈希清单、安装包及回退说明；不发布多个中间安装版本。

## 11. 必须通过的回归场景

| 场景 | 预期结果 |
| --- | --- |
| 刷新期间先收藏再取消收藏 | 保留最后一次操作，不被刷新开始时的快照覆盖 |
| 刷新期间关联论文并创建任务 | 刷新及重启后关联和任务均可追溯 |
| 同名近似、明确不同 ISSN | 不继承对方分区、出版社和费用 |
| 不同 ISSN 但权威信息证明为同刊印刷/电子版 | 正确归并，不误判身份冲突 |
| 旧高分特刊提前关闭，截止仍在未来 | 推荐、小组件与新通知全部移出，收藏保留 |
| 已过期记录收到可信延期证据 | 重新请求、更新日期、恢复有效状态并记录变更 |
